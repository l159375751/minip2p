# POC10 → POC13 Parity Audit

POC13 is the maintainable Vite SPA we’re evolving into a product. POC10 is the monolithic HTML demo that already proved the full librarian workflow (search, respond, download, diagnostics). This document captures what each does today and the gaps we must close to claim “feature parity.”

## Architecture Snapshots

- **POC13 (“current app”):** Modular Vite build (ESM), manifest-driven shelf + library list, Nostr search publisher/responder (kind 25555/25556), library sharing toggle (kind 33333), IndexedDB persistence, Vitest coverage, deploys via `npm run build` → `poc13/`.
- **POC10 (“reference demo”):** Single HTML file with inline JS/CSS, CDN-loaded nostr-tools/WebTorrent/PeerJS, full-text Gutenberg index loader (~9 MB), auto-responder daemon (kinds 25555‑25560), “who-has” transport negotiation, WebTorrent download controls, detailed log panels for nostr/search/transfer events.

## Restoration Work Packages

1. **Responder/Diagnostics:** Finish Nostr responder parity (rate limiting, counters, log feed, daemon toggles, relay selector).
2. **Index & Manifest:** Port Gutenberg index loader (stream + parse) so search fallback isn’t hardcoded samples.
3. **Discovery Protocol:** Implement kind 25557/25558 flows, including UI to request availability and show offered transports.
4. **Transfers:** Integrate WebTorrent/WebRTC modules (from POC10 & POC12) with progress UI, peer counts, and download controls.
5. **Library Share/Import:** Allow subscribing to others’ library share events + importing into local store with dedupe and UX feedback.
6. **Telemetry Surface:** Replace placeholder panel with real-time log/diagnostic cards (relay health, responder stats, downloads, storage).
7. **Relay/Peer Management:** UI to add/remove/test relays + view connection state, mirroring POC10 controls but with refined styling.

Each work package can be implemented independently while keeping the SPA lean; finishing all of them yields full POC10 functionality with the benefits of the new architecture.
